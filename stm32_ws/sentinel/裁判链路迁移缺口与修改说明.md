当前裁判链路缺口 = 缺少 USART1 接收字节进入 FIFO 的输入链、缺少 FIFO 字节队列模块、缺少裁判解包任务、缺少业务 getter 与接收超时状态。

需要从老工程移入的文件：
- `User/APP/referee_usart_task.c`
- `User/APP/referee_usart_task.h`
- `User/Controller/fifo.c`
- `User/Controller/fifo.h`

建议落点：
- `referee_usart_task.c/h` 放入 `User/APP`，因为它是固定周期任务入口，职责是初始化裁判数据、初始化 FIFO、每 10 ms 执行解包状态机。
- `fifo.c/h` 放入 `User/Controller`，因为它提供通用字节队列，职责是让 USART1 空闲回调写入字节、裁判解包任务按字节读取。

移入后的工程纳入项：
- `MDK-ARM/CtrlBoard-H7_WS1812.uvprojx` 增加 `referee_usart_task.c`、`referee_usart_task.h`、`fifo.c`、`fifo.h`。
- Include Path 增加 `..\User\Controller`，`User/APP` 已在工程内时保持原路径。

`bsp_usart.c/h` 修改机制：
- `bsp_usart.c` 保留 `usart1_buf[2][USART_RX_BUF_LENGHT]` 和 `referee_fifo_buf[REFEREE_FIFO_BUF_LENGTH]`。
- 增加 `fifo_s_t referee_fifo` 的全局对象声明。
- USART1 空闲回调流程改为：接收 `usart1_buf[x]` 数据 -> `fifo_s_puts(&referee_fifo, usart1_buf[x], Size)` -> 切换双缓冲索引 -> `HAL_UARTEx_ReceiveToIdle_DMA(&huart1, usart1_buf[x], USART_RX_BUF_LENGHT)`。
- USART1 错误回调流程保留清缓冲和重启 DMA。
- `bsp_usart.h` 导出 `referee_fifo`、`referee_fifo_buf`、`usart1_buf`，让裁判任务完成 FIFO 初始化。

`referee_usart_task.c/h` 修改机制：
- `referee_usart_task()` 启动后调用 `init_referee_data()`。
- 调用 `fifo_s_init(&referee_fifo, referee_fifo_buf, REFEREE_FIFO_BUF_LENGTH)`。
- 循环周期 10 ms，调用 `referee_unpack_fifo_data()`。
- 状态机步骤保持 `STEP_HEADER_SOF -> STEP_LENGTH_LOW -> STEP_LENGTH_HIGH -> STEP_FRAME_SEQ -> STEP_HEADER_CRC8 -> STEP_DATA_CRC16`。
- CRC8 通过后继续收完整帧，CRC16 通过后调用 `referee_handle_data(protocol_packet)`。

`referee.c/h` 修改机制：
- 增加 `uint32_t g_referee_last_rx_ms`。
- `init_referee_data()` 清零所有裁判结构体并把 `g_referee_last_rx_ms` 置 0。
- `referee_handle_data(uint8_t *frame)` 先写入 `g_referee_last_rx_ms = HAL_GetTick()`，再复制 5 字节帧头、读取 2 字节 `cmd_id`、按 `cmd_id` 写入对应全局结构体。
- 保留 `referee_data_solve()` 作为兼容入口，内部调用 `referee_handle_data()`。
- `referee_data_available(timeout_ms)` 定义为：robot_id 在红方 1-7 或蓝方 101-107 内，且 `HAL_GetTick() - g_referee_last_rx_ms <= timeout_ms`。
- `get_chassis_power_and_buffer(uint16_t *power_limit, uint16_t *buffer)` 输出 `robot_status.chassis_power_limit` 和 `power_heat_data.buffer_energy`。
- `get_shoot_heat0_limit_and_heat0(uint16_t *heat_limit, uint16_t *heat)` 输出 `robot_status.shooter_barrel_heat_limit` 和 `power_heat_data.shooter_17mm_barrel_heat`。
- `get_shoot_heat1_limit_and_heat1(uint16_t *heat_limit, uint16_t *heat)` 输出 `robot_status.shooter_barrel_heat_limit` 和 `power_heat_data.shooter_42mm_barrel_heat`。

`protocol.h` 修改机制：
- `REF_PROTOCOL_FRAME_MAX_SIZE` 统一为 192。
- `REF_PROTOCOL_CMD_SIZE` 建议同步命名为 `REF_PROTOCOL_CMDID_SIZE`，保留兼容宏 `#define REF_PROTOCOL_CMD_SIZE REF_PROTOCOL_CMDID_SIZE`。
- `REF_HEADER_CRC_CMDID_LEN` 保持 `REF_PROTOCOL_HEADER_SIZE + REF_PROTOCOL_CMDID_SIZE + REF_PROTOCOL_CRC16_SIZE`。

`robot_param.h` 修改机制：
- 删除或避开 `REF_PROTOCOL_FRAME_MAX_SIZE` 的重复定义，最大帧长只由 `protocol.h` 提供。
- 保留 `REFEREE_FIFO_BUF_LENGTH 1024` 与 `USART_RX_BUF_LENGHT 64`。
