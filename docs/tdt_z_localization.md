## 1. 一句话概括

一套 **ROS 2 Humble + C++17 的激光惯性定位栈**，把「LIO 前端维护 odom」与「先验地图/UWB
维护 map→odom」彻底拆开：前端只管局部里程计，后端用**因子图**把先验图配准、回环、UWB 作为
观测融合进来，并用状态机处理退化与重定位。前端（ZLIO）可单独当里程计用，后端也留了接口
可接别人的 LIO 前端或奥丁之眼。

范围只覆盖**定位**：不含导航、决策、云台、弹道。

---

## 2. 总体架构

| 角色 | 职责 |
|---|---|
| 前端（ZLIO） | 维护 **odom 系**内的运动：LiDAR + IMU 更新局部里程计，自建局部地图；把去畸变点云 + 同时刻里程计打包送后端；用 IMU 高频传播实时位姿 |
| 后端 | 维护 **map → odom**：从观测中挑关键帧，把全局位姿放进因子图优化，输出 TF、协方差与定位状态 |
| 建图侧 | bag 回放建图 → 保存地图包 → 自动清理动态残影 → CloudCompare 精修 → 生成先验地图包与描述子 |

**为什么要拆开（作者原话的要点）**：

- 以前直接把先验图灌进 LIO，LIO 是紧耦合的、发散不好判断，常常要等到速度/加速度离谱了才发现。
- 拆开后可以对先验图配准的**海森矩阵做可观测性分析**，直接判断匹配与定位有没有异常。
- 前端不必每次高频更新都去访问一张巨大的先验图，开销更低。
- 没有先验地图时（建图环节被取消的适应性训练）可接 UWB：跑几米后 yaw 可观测，即可无图定位。
- 定位恢复更容易：前端可直接重启继续维护自己的里程计，全局位姿恢复交给后端单独做。

## 3. 前端 ZLIO

### 3.1 误差状态建模

不走 FAST-LIO 的「直积流形」建模，而用 **SE₂(3) ⋉ se(3) 半直积**结构，把导航状态与 IMU 零偏
一起纳入误差变换，使姿态与速度部分的噪声误差可以精确线性化，减少这两部分的线性化误差。
理论依据见文末参考文献 [1]（*Equivariant Symmetries for Inertial Navigation Systems*）。

### 3.2 初始化（不要求静止）

比赛里定位飞掉重启时云台可能还在跟随自瞄转动，静止假设不成立。做法：

1. 用一小段 IMU 给重力方向初值；
2. IMU 传播 + 点云粗配准得到初步轨迹；
3. 积累一段时间后，把**多帧点云共面约束 + IMU 预积分**放进同一窗口联合优化
   位姿、速度、零偏与重力方向；
4. 每轮优化后用新轨迹**重新去畸变**，迭代收敛；
5. 收敛后把坐标系对齐重力，用窗口末帧状态 + 累积点云建滤波器初值与初始地图。

### 3.3 去畸变

采用 **DLIO 思路**：用 IMU 构造**分段连续轨迹**，按每个点的采样时刻做运动补偿。
把加速度转到 odom 系并加入重力得到实际运动加速度，再由相邻 IMU 估计角加速度与加速度变化率，
构造该区间的姿态与位置轨迹（**位置按三次多项式**，姿态由区间内变化的角速度积分）。
同区间内的点复用轨迹参数，逐点代入时间即可，开销可控。补偿后统一到本次观测结束时的 IMU 系。

对比：FAST-LIO 类按帧首尾位姿做线性插值补偿，云台转动或加减速时误差明显。

### 3.4 地图结构（VoxelMap + 点矩统计）

结构沿用 VoxelMap：哈希表索引体素，体素内部用八叉树组织平面——能用一个平面描述就存平面，
否则继续细分，直到满足平面条件或到最大深度。平整区域用大体素，几何复杂处用小体素。

**作者的改动**：平面建立后，用**累计点矩统计量（点数 N、一阶矩 s、二阶矩 Q）代替原始支持点**。
新点到达时只更新统计量，再由统计量重算平面中心 `c` 与散布矩阵 `A`，
取 `A` 最小特征值对应的特征向量作法向；达到更新上限后进一步释放统计量，只留匹配所需的平面信息。

实测开销下降（原文表格）：

| 数据 | CPU 时间减少 | 峰值内存减少 |
|---|---|---|
| Mid360 ramp | 72.8% | 86.6% |
| Mid70 TN0 | 62.6% | 90.7% |

### 3.5 面建模与残差（把「平面本身不准」计入权重）

- 平面中心与法向带有不确定性（由建图点误差与位姿误差引起）；
- 墙面/地面并非理想平面，局部点相对拟合平面的散布也要计入，记为方差 `τ²`
  （从支持点法向散布中扣掉可解释的已知噪声）；
- 点面残差方差 = 测量协方差贡献 + `τ²` + 平面参数协方差贡献；
- 关键一点：**同一地图平面上的多个点共享平面误差**，若按独立处理，点数越多滤波器越会
  过度相信这个平面。于是按匹配到的平面分组，保留组内相关性
  （`Cov(r_i, r_j) ≈ h_i Σ_π h_jᵀ`），在平面的三个误差自由度内联合消去共享误差，
  再把整组约束交给滤波器，避免构造随点数增长的大协方差矩阵。

### 3.6 时空自适应

- **时间自适应**：介于 FAST-LIO 的整帧更新与 Point-LIO 的逐点更新之间。把点云按采样时刻切成
  连续小段，每段各自去畸变 + 一次滤波更新；再由近期线加速度、角加速度和当前点面观测的
  信息矩阵决定下一次更新间隔——运动剧烈且影响明显时缩短，否则延长积累更多点。
  （原文给出二阶运动项近似 `e²(Δt) ≈ Δt⁴/4 · κᵀΛ̄κ` 与 clip 后的目标间隔公式。）
- **空间自适应**：用保留窗口内代表点到雷达的**距离中位数**（近期平滑）作为场景尺度，
  推导目标点数；再按点数误差及其变化率，用一个小 **PD 控制**调整采样体素边长。
- 实测效果：在场地「洞」附近时间窗口与空间采样率反应最明显。

### 3.7 动态点滤除：明确没做在线

试过在线滤除动态点，没能同时兼顾开销与滤除率；且本场景特征主要来自墙壁与棚顶，
前后差距很小，最终**不在前端做在线动态点滤除**，只提供**离线工具**在建图后清理保存的地图。

## 4. 后端定位

### 4.1 因子图

- 节点 = 关键帧的 map 系位姿；**固定时长滑动窗口** + 窗口外边缘化，保留对后续的约束。
- **锚点先验**：初始化/恢复成功后，把可信位姿作为锚点固定轨迹起点。
- **里程计因子**：前端给出的相邻关键帧相对运动。
- **先验图配准因子**：扫描与先验地图配准得到的位姿 + **该次配准的约束强度**（可观测性分析
  的产物直接进图）。
- **回环因子**：无先验地图时使用。
- **UWB 因子**：约束天线位置；开启在线标定时把 UWB 系→map 的对齐与**时间偏置**作为
  共享变量长期留在图中，并给时间偏置加先验。
- **重力方向因子**：无先验地图且启用 UWB 时，用前端重力方向约束横滚/俯仰。

### 4.2 状态机（五种状态）

| 状态 | 含义与处理 |
|---|---|
| `INITIALIZING` | 等待首次定位成功 |
| `NORMAL` | 正常定位 |
| `OBS_DEGRADED` | 点云质量差、观测弱，或全局观测与预测冲突但证据不足；**拒绝冲突校正**，沿用前端相对运动；后续校正通过验收则回到 NORMAL |
| `SUSPECT` | 冲突持续达阈值，或速度异常、当前位姿已无法支持局部匹配（前端在漂但没炸）；保留前端，用地图/描述子/UWB **重新求 map→odom** |
| `LOST` | SUSPECT 连续失败或估计器故障；**重置前端**重建局部里程计，再靠先验图或 UWB 找回全局位姿 |

进入 `SUSPECT` / `LOST` 后若已有可信位姿，**输出冻结在该位姿**直到恢复成功。

> 这是全文对我们最有参考价值的部分：把「匹配质量差」拆成「观测弱」和「位姿不准」两类，
> 再把「位姿不准」拆成「漂移」与「发散」，分别对应不同的恢复手段。

### 4.3 描述子

作者的定位很直白：**描述子 = 点云查询的键值对**，键用来找候选位置，再靠配准确认位姿；
因此最关心相似度在候选上的分布是否足够尖峰。

- **Scan Context（SC）**：适合 Mid-360。按距离/方位切环与扇区，格内存最高点高度；
  比较时尝试不同旋转找最相似位置与朝向，顺带给配准提供 yaw 初值。
  比赛地图只有约 200 个描述子，**不用 KD-tree，直接遍历**。
  SC 对高度分布敏感，生成与查询前都必须做**重力矫正/调平**。地图精修后建议用离线工具
  按网格重新生成描述子（比建图时直接保存的质量更好）。
- **G-PROBE（GP）**：面向 Avia / 奥丁之眼这类有限视场。把点云表示为带占据概率与不确定性的
  二维网格，地图侧准备不同朝向的视场分支；检索时比较共同可见区域的占据与高度分布，
  并降低「多个朝向都相似」的候选得分。**作者明确说这部分没充分测试、召回率达不到 100%，
  建议自行调参并慎重使用。**

### 4.4 配准与验收

- 正常跟踪时积累近期点云，按预测位姿取附近先验子图做点到面配准；初值好直接细配，
  对应点不足或残差大时先粗配准再回细层。
- **弱观测下的求解参考 DCReg**：走廊里沿走廊方向移动时点云仍贴得住两侧墙面，
  该方向的位置偏差难以判断。做法是用 **Schur 补分别分析平移与旋转**，
  按弱方向构造**预条件器**改善数值条件。
- 配准后按残差尺度与海森矩阵**白化**位姿误差：强方向权重大、弱方向权重小、
  不可观方向不加约束；再结合图预测的不确定性，用 **NIS 与卡方检验**决定是否接受。
- 正常跟踪允许只用部分方向约束；**初始化与重定位要求完整位姿通过验收**才确定 TF、建立锚点。

### 4.5 UWB 初始化

无先验地图时 UWB 只给位置，单个位置定不了 odom 与全局系的 yaw。把同一时刻的前端天线位置
与 UWB 位置配对，通过一段运动求两条轨迹间的**平移与 yaw**（横滚俯仰沿用前端重力方向）。
可观测性分析结论：**静止时 yaw 不可观测**，轨迹在水平面展开后航向信息才增加——
所以默认要求至少 **3 m** 的水平位移跨度才能进入 `NORMAL`。

### 4.6 Reset

重置时后端冻结输出并请求前端重置；前端重新提供里程计与点云后，后端接续或重新确定
map→odom 恢复输出。作者自己也说这套逻辑偏复杂，简单场景下「一个普通的重置服务大概也就够用了」。

## 5. 工程面（仓库侧）

| 项 | 内容 |
|---|---|
| 环境 | Ubuntu 22.04、ROS 2 Humble、C++17、CMake ≥ 3.16、colcon |
| 依赖 | Eigen ≥ 3.3、**GTSAM 4.2.x**、PCL、yaml-cpp、nanoflann、OpenMP、oneTBB、Livox ROS Driver 2 / Livox-SDK2 |
| 包 | `frontend`（ZLIO）、`backend`、`bringup`、`livox_ros_driver2`、`localization_interfaces` |
| 配置 | `config/lio.yaml`（前端）、`config/backend.yaml`（后端） |
| 模式 | `mode:=mapping`（建图 / 无图 + UWB 实时定位）、先验定位 |
| 建图流程 | `ros2 bag play --clock` 建图 → `/stop` → `/backend_node/save_map` → `clean_map_bundle`（思路参考 FreeDOM）→ CloudCompare 手修 → 生成地图包与描述子 |
| 许可 | GPL-2.0-only（与文章 CC BY-NC-SA 4.0 不同，代码商用需注意） |
| 作者自述 | 参数很多，安装外参/场地路径/UWB 设置均来自作者设备，**不是通用标定结果**；代码经 AI 整理并人工审查 |

性能（原文）：开启先验地图 + UWB 时，前后端一起运行的裸负载 CPU 约 **15%**（100% = 一个逻辑核）；
后端内存占用相对高，是空间换时间，可通过参数压低。

## 6. 作者承认的局限

- 前端在 IndoorOffice1（Mid-360 室内数据，13 种前端方法/模式、三次运行取中位）上
  「精度、CPU、内存都不错，但没有在所有指标上胜出」。
- 后端只做工程处理，**没有合适手段单独测精度**，只展示开销。
- G-PROBE 部分召回率不到 100%，未充分测试。
- 在线动态点滤除没有实现。

## 7. 与本工程的对照（我的观察，未经实测）

我们当前是 `point_lio → small_gicp_relocalization（2 Hz，出 map→odom）→ Nav2`
（见 [`localization_roadmap.md`](localization_roadmap.md)）。对照这份开源：

| 维度 | 本工程现状 | TDT |
|---|---|---|
| map→odom 来源 | 单次 small_gicp 配准，无约束强度输出 | 因子图，配准结果带**约束强度**参与优化 |
| 退化处理 | 无状态机；配准失败时沿用上次 TF | 五态状态机，可区分「观测弱」与「位姿不准」，必要时冻结输出 |
| 重定位 | 只有启动时 GICP 对齐 | 描述子（SC/G-PROBE）检索 + 完整位姿验收 |
| 无图定位 | 无（依赖先验 PCD） | UWB + 前端，跑开 3 m 后 yaw 可观测 |
| 点云地图 | 保存全部点 | 保存**点矩统计量**，内存降一个量级 |

可低成本借鉴、且不需要换掉整个栈的点：

1. **配准验收**：给 `small_gicp` 的配准结果加残差/海森白化 + NIS 卡方门槛，不合格就不更新 TF
   —— 我们 memory 里「map→odom 修正稳定但 1.16° 偏角」这类问题，至少能判定「这次配准可不可信」。
2. **状态机思路**：至少区分「点云弱」与「位姿漂」，避免把可疑 TF 直接喂给代价地图
   （与「静止时 /map 0x0 死锁」是同一类问题：系统不知道自己在退化）。
3. **地图统计量压缩**：先验 PCD 只用于 GICP，改存平面统计量能显著降内存，但要重写配准侧。

**不建议直接替换**：整套引入需要 GTSAM 4.2.x（Ubuntu 22.04 的 apt 没有，要源码编译）、
`livox_ros_driver2`（我们已用官方 `livox_ros_driver2` + Mid-360），
且它的外参与场地参数都不是我们的，直接跑起来会先撞到标定问题。
